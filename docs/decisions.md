# 决策记录

> 记录已经确认的事实、暂定假设和仍未决定的事项。新信息到来后可以追加，不要偷偷改写历史。

## 已确认

| 项目 | 当前决定 | 来源 |
|---|---|---|
| 初始设备 | 先做电脑端，朋友也先用电脑体验 | 团队讨论 |
| 后续交互 | 手势和手机端留到后续 | 团队讨论 |
| 后续内容 | 音乐、录音、热点、多图展览、电影多画面留到后续 | 团队讨论 |
| 讨论方式 | 共同大纲 + 独立反馈文档 + Pull Request | 团队讨论 |
| 仓库可见性 | 公开 | 创建仓库时确认 |
| 当前阶段 | 先讨论和规划，不立即开始完整开发 | 团队讨论 |

## 暂定假设

| 假设 | 为什么暂定 | 如何验证 |
|---|---|---|
| 单张普通照片可以做出有限空间感 | 方向上可行，但效果取决于素材和路线 | 用 1-2 张授权照片做小实验 |
| 2.5D/视差可能比完整 3D 更适合第一版 | 对学生团队和时间更友好 | 比较生成时间、效果和交互稳定性 |
| 需要快速预览和较高质量结果两种模式 | 可以兼顾演示速度和效果 | 记录实际耗时、显存和失败率 |
| AI 需要参与素材判断、路线选择或解释 | 这样更符合智能体方向 | 在流程中加入一个可观察的决策点 |

## 尚未决定

- 是否需要真实 3D 网格；
- 是否使用本地模型、云端模型或现成服务；
- 是否需要账号、上传存储和分享链接；
- 比赛的最终赛道规则和提交格式；
- 队友姓名、分工和每周投入时间；
- 是否需要申请预算或购买 API。

## 记录规则

- “建议”不自动变成“决定”；
- 有争议的内容写进反馈文件；
- 只有团队确认后才把内容移入“已确认”；
- 技术实验要记录日期、输入素材、运行环境、结果和失败原因。
