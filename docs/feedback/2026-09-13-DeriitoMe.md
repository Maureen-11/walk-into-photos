## 1. 我理解的目标

用户在自己的电脑浏览器里上传一张普通照片，系统在没有人工建模的前提下生成一个空间化场景，让用户能有限地移动视角、产生视差，从而获得"走进去看了一眼"的感觉。第一版追求的不是测量意义上的真实重建，而是一个普通观众能在 30 秒内理解并完成的可交互体验，同时明确告诉观众：哪些部分是原照片，哪些部分是模型估计出来的。

## 2. 我最赞成的三点

1. 把"走进去"先定义为可交互的视觉体验，而不是承诺真实 3D 重建。这个边界定得准，也保住了答辩时的可信度。
2. 明确写了"失败也要可展示"，并且提前规划了降级路径。演示现场最怕的不是效果不够好，而是直接黑屏。
3. 把音乐、录音、多图展览、手机端、手势都放到后续方向，没有让第一版失焦。

## 3. 我最担心的三点

1. **第一版的产物形式还没定，两条线暂时无法并行。** 大纲第 5 节列出了 A/B/C 三条候选路线，但"当前建议"仍是暂定的。产物究竟是深度图、3D 高斯文件，还是带贴图网格，直接决定展示侧要加载什么、要写什么。这一条不定，协作就只能互相等。
2. **参考项目与许可证没有登记。** README 引用的外部项目里，`apple-aiml-research/ml-sharp` 使用的是 Apple 自定义许可条款（GitHub 标记为非标准许可），`stable-virtual-camera` 是 Stability AI 非商用许可；而 `WonderWorld` 与 `elsewhere` 的仓库根目录没有 LICENSE 文件，按默认规则属于保留所有权利。在这些结论没有写清之前，不适合把它们写进比赛材料当作"我们的能力"。
3. **演示环境的可达性没有核验。** 我在本机实测：`huggingface.co` 直连返回 000（不可达），`hf-mirror.com` 返回 200。如果第一版方案依赖运行时下载模型权重，而现场网络同样连不上，演示会直接失败。这类风险应该提前记录，而不是留到录屏当天。

## 4. 我建议第一版必须保留

- 单张图片上传 → 处理 → 浏览器内可交互的完整短路径；
- 至少一种有限视角移动（建议先做视角转动加轻微位移，不承诺自由行走）；
- 明确的加载中、失败与降级提示；
- "哪些是原图、哪些是模型估计"的说明层；
- 生成结果能在另一台电脑上被打开体验。

## 5. 我建议暂缓

- 真实 3D 网格与自由行走；
- 多图或视频输入；
- 账号体系、云端模型与持久化存储；
- 分享链接的长期存储（第一版用本地文件或静态托管即可）；
- 手机端适配与手势控制。

## 8. 给项目的具体建议

### 已经查到或实际验证的事实

- 截至 2026-09-13，本仓库共 9 个文件、8 次提交，只有 `main` 一个分支，无 Issue、无 Pull Request，仓库内没有任何代码文件，也没有 LICENSE 文件。
- README 中引用的 `apple/ml-sharp` 现已重定向到 `apple-aiml-research/ml-sharp`（约 8.9k star），其许可证为 Apple 自定义条款，不属于标准开源许可。
- `stable-virtual-camera` 采用 Stability AI 非商用许可；`WonderWorld` 与 `elsewhere` 的仓库根目录没有 LICENSE 文件。
- `WonderWorld` 官方 README 写明运行需要 48GB 显存；`DimensionX` README 写明单卡约需 26–30GB 显存。两者都超出常见学生设备的范围。
- 本机实测网络：`huggingface.co` 返回 000（不可达），`hf-mirror.com` 返回 200，`registry.npmjs.org` 正常。
- 本机实测环境：NVIDIA RTX 4060 Laptop（8GB 显存）、Node 24 与 npm 11 可用、Python 为 3.14 且未安装 conda。
- 浏览器端存在已核实的可用组合：`onnx-community/depth-anything-v2-small`（Apache-2.0，transformers.js 生态，量化后最小约 18.2MB）。

### 基于事实的推测

- 在 8GB 显存与有限周期的前提下，第一版走"单张图片 → 深度估计 → 位移网格 → 浏览器视差"的 2.5D 路线，落地概率明显高于直接做 3D 高斯重建。
- 如果最终要做 3D 高斯，更现实的做法是接入现成的前馈模型，而不是自行训练或自行实现重建算法；但这需要先解决许可证问题，否则不能写进比赛材料。
- 团队现有的公开项目集中在 Web 与数据类方向。把 3D 部分定位为"集成并验证现成模型"，比定位为"自研重建算法"更容易在限定时间内产出可演示结果。

### 个人偏好或创意建议

- 建议第一版优先做纯浏览器方案：照片不出本机、无服务器、无上传隐私风险。这个特性本身就是答辩时很有说服力的一点。
- 建议把"诚实层"做成产品的一部分：常驻一句能力说明，再加一个"查看深度估计结果"的开关，主动展示模型的估计边界。
- 建议把"另一台电脑能打开"设为硬指标，因为它直接对应比赛现场与朋友试用的真实场景。
