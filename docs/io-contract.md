# 场景包接口契约 v0.1（提案）

> 状态：提案，尚未成为团队决定。本文只约定**中间产物的格式**，不决定采用哪条技术路线。
> 提出人：DeriitoMe　最后更新：2026-09-13
> 相关文档：[项目大纲](project-outline.md)、[决策记录](decisions.md)

## 1. 这份文档要解决什么问题

大纲第 5 节的路线还没有结论，于是有两件事无法并行：模型侧不知道要交出什么，展示侧不知道要加载什么。本文把两者之间的**交接面**固定下来。

只要产物符合本契约，展示层就能独立开发和测试；只要展示层依赖本契约，模型侧就可以自由选择 A、B、C 任意路线。契约只规定"长什么样"，不规定"怎么算出来"。

## 2. 不变量

无论走哪条路线，以下几条都应成立：

1. **单一输入**：一次处理只接收一张图片。
2. **产物自描述**：一个场景包是一个目录，由目录内的 `scene.json` 描述其余文件是什么。
3. **可离线打开**：场景包放到任意静态服务器或本地文件系统都能被打开，不依赖生成时的进程或数据库。
4. **来源可追溯**：看得出产物由哪张图、哪个模型、什么时间生成。
5. **能力可声明**：能区分"原图内容"与"模型估计内容"，供界面做诚实提示。
6. **前端可降级**：可选文件缺失时退到较低保真度的展示方式，而不是直接报错。

## 3. 输入约束

| 项目 | 约定 |
|---|---|
| 允许格式 | `jpg`、`jpeg`、`png`、`webp` |
| 暂不接受 | `heic`、`gif`、多图、视频 |
| 尺寸下限 | 最短边 ≥ 768px |
| 尺寸上限 | 长边 ≤ 4096px，超出则等比缩小后再处理 |
| 文件大小 | ≤ 20MB |
| 推荐内容 | 室内、教室、走廊、街道、自然风景等结构相对明确的场景 |
| 不推荐内容 | 人物特写、证件，以及明显包含他人隐私信息的画面 |

超限时统一给出可读提示，并说明原因属于"尺寸不足""尺寸过大"还是"格式不支持"。

## 4. 场景包目录结构

```
<scene-id>/
├── scene.json          必需  清单文件
├── source.jpg          必需  原图（等比缩小后的版本）
├── depth.png           必需  16 位灰度深度图
├── preview.jpg         必需  缩略图，用于列表与分享预览
├── mesh.glb            可选  带贴图网格（B/C 路线可能产出）
└── scene.splat         可选  3D 高斯文件（B 路线可能产出）
```

命名约定：`<scene-id>` 仅使用小写字母、数字与连字符，不含中文与空格。

## 5. scene.json 字段

```json
{
  "version": "0.1",
  "source": {
    "file": "source.jpg",
    "width": 1600,
    "height": 1067,
    "sha256": "…"
  },
  "depth": {
    "file": "depth.png",
    "bit_depth": 16,
    "encoding": "u16-inverse-depth-normalized",
    "model": "depth-anything-v2-small",
    "license": "Apache-2.0"
  },
  "camera": { "fov_y_deg": 50 },
  "preview": { "file": "preview.jpg" },
  "provenance": {
    "generated_at": "2026-09-13T12:00:00+08:00",
    "pipeline": "25d-parallax-v0.1",
    "is_generated": true
  },
  "rights": {
    "source_type": "own-photo",
    "credit": "",
    "license": ""
  }
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `version` | 是 | 契约版本，两段式 |
| `source.file` / `width` / `height` | 是 | 原图文件名与像素尺寸 |
| `source.sha256` | 是 | 原图哈希，用于确认产物与图片对应 |
| `depth.file` | 是 | 深度图文件名 |
| `depth.bit_depth` | 是 | 固定为 16 |
| `depth.encoding` | 是 | 深度语义标识，见下 |
| `depth.model` / `depth.license` | 是 | 产出深度的模型与其许可证 |
| `camera.fov_y_deg` | 否 | 竖直视场角，缺省由前端取 50 |
| `preview.file` | 是 | 缩略图文件名 |
| `provenance.*` | 是 | 生成时间、流水线标识、是否为生成内容 |
| `rights.*` | 是 | 素材来源类型、署名与许可证 |

`encoding` 取值约定：

- `u16-inverse-depth-normalized`：16 位无符号，数值越大表示越靠近相机，已归一化到全量程。这是默认值。
- 若将来引入米制深度，新增 `u16-metric-depth-mm`，不改变已有取值的含义。

`rights.source_type` 取值：`own-photo`、`licensed`、`public-domain`、`unknown`。取值为 `unknown` 时，前端必须显示来源不明的提示。

## 6. 版本与兼容

- `version` 采用"主版本.次版本"两段式。
- 前端遇到**不认识的字段应忽略**；遇到**主版本不一致应拒绝加载**，并提示"该场景由更新版本的流程生成"。
- 次版本升级只允许新增可选字段，不允许改变已有字段的含义。

## 7. 错误与降级

处理侧与展示侧共用同一套错误码：

| 错误码 | 含义 | 用户可见文案 | 降级路径 |
|---|---|---|---|
| `E_INPUT_FORMAT` | 格式不支持 | 请上传 JPG、PNG 或 WebP 图片 | 无 |
| `E_INPUT_TOO_SMALL` | 尺寸不足 | 图片太小，建议最短边不低于 768 像素 | 允许强制继续 |
| `E_INPUT_TOO_LARGE` | 尺寸过大 | 图片过大，已自动缩小后处理 | 自动处理 |
| `E_MODEL_UNAVAILABLE` | 模型不可用 | 模型加载失败，已切换到示例演示 | 使用内置示例场景 |
| `E_RESOURCE_LIMIT` | 算力或显存不足 | 当前设备不支持高质量模式 | 切到低质量或示例 |
| `E_TIMEOUT` | 处理超时 | 处理时间过长，已停止 | 切到示例或重试 |

原则：任何失败都必须保留一条能继续演示的路径，不允许只留下黑屏。

## 8. 展示侧消费流程

1. 读取 `scene.json`，校验 `version` 的主版本。
2. 校验 `source.file`、`depth.file`、`preview.file` 是否存在。
3. 若存在 `mesh.glb` 或 `scene.splat`，按对应模式渲染；否则回退到深度视差模式。
4. 依据 `provenance.is_generated` 显示能力说明。
5. 依据 `rights.source_type` 决定是否显示来源提示。
