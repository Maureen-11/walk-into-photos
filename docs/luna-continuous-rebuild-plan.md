# 走进照片：Luna 连续执行与验收计划

日期：2026-09-14。状态：待执行。本文仅是计划，不表示模型已安装、效果已通过或工程已完成。

本计划完整保留原实测与重建计划的技术任务，改为一次启动、连续推进。执行方式以本文为准，替代旧文档“本次只执行 T00”等逐项等待指令；旧文档保留为历史。此次仅编写计划，不启动工程实施；日后启动仍不包含自动发布、上传照片、购买服务或删除数据。

## 1. 已确认的产品边界

- 场景：从原拍摄位置出发，在有限、连续的空间里前进、绕行、回头；地形允许飞行。不能以照片缩放或微小视差替代。
- 主体：猫咪、人物等以鼠标或点击回应为主，不强制环绕。沿用预生成短动作、交互触发的方式；动作须保持主体特征与背景稳定。
- 不可见区域允许采用颜色、氛围相符而细节简化的立体补全；允许物体重建后细节不同，但须标明创作区域，不声称真实复原。
- 八类目标保留：自然、室内、街道、建筑、动物、人物、食物、艺术／旧照片。分类成功不等于该类体验完成。
- 正常照片允许上传与尝试；生成失败可以明确失败、建议替代路线，不允许假成功。
- 本地照片处理，模型与环境放 D 盘；目标 Windows、6GB／8GB 显存分别实测。两台电脑不能合并显存；单模型超限不能靠顺序加载解决。
- 摄像头手势、手机、音乐、多照片展览暂缓。保留动作事件接口即可。
- 无每日安排，按验收关口推进。新 UI 以后重做，生成逻辑与布局必须解耦。

## 2. 已发现的问题与禁止的捷径

执行前复核当前代码，以下是编写时的发现，不代替实时检查：

1. 真实几何分支统一执行 MoGe；模板没有落实独立的场景重建。
2. 快速／完整主要区别是默认 768／1280 输入尺寸；没有完整的主体建模、遮挡纹理补全和质量验收。
3. 生成文件后进入 FULL_READY；生成结束与质量合格混淆。
4. PhotoBackdrop 跟随镜头，覆盖率低时原图与破碎网格叠加，产生重影。
5. 统一深度归一化、固定高度或边界不能建立可信尺度、坡面行走和碰撞。
6. “不可见区域由 MoGe 补全”表述超出当前实现能力。

禁止人为延迟凑够十分钟；禁止仅升分辨率就称完整版；禁止原图遮洞、强制缩小活动范围来冒充验收；禁止以测试通过代替视觉检查。

## 3. Luna 执行协议

一次启动覆盖 T00—T10；同一时刻聚焦一个边界明确的任务，通过验收后自动进入下一项，无须用户重复发送“继续”。开始前读取 AGENTS.md、当前差异、相关文件；保留所有既有未提交修改。复杂几何与集成任务建议 high/xhigh，简单文字与排序 medium；推理强度不改变验收条件。

通用禁止范围：真实 .env 内容不得输出；不得上传照片、权重或私人日志；不得覆盖其他任务文件；不得批量回滚脏工作区。依赖安装使用独立 D 盘环境，先检查磁盘、权重来源和许可。外部接口读官方代码后使用，不猜参数。

每项提交本地报告 `docs/reports/rebuild-Txx.md`：实际修改、命令与退出码、成功／失败／未验证、证据路径、耗时、显存测量方法、剩余问题。截图、视频、生成模型在 git 忽略的本地证据目录；报告仅放不含私人路径的相对引用。提交 Git 前审查差异，仅暂存本任务文件或补丁，禁止 git add .；不自动推送。

失败回退通则：保留失败记录和可用旧结果；停用本任务新提供器或入口，不能回滚用户更改。资源不足时记录并转下一个已批准候选；产品体验取舍需要用户看证据决定，不能静默降级。

现有命令：后端目录运行 `..\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider`；前端目录运行 `pnpm run build`。先确认解释器与包管理器可用。纯文档任务无需重复全量测试。

下文标为“新建”的脚本现在并不存在；对应任务负责先实现脚本和 --help，再运行。脚本接受显式输入与输出目录，失败返回非零码，不可内置样片文件名、类别答案或成功分数。

## 4. 数据与完成状态约定

- generation_status：queued/running/generated/failed/cancelled/interrupted。
- validation_status：not_run/passed/failed/needs_review；generated 不得自动变成 passed。
- 阶段记录：stage、provider、模型 revision、参数摘要、开始结束时间、产物、失败／跳过原因；进度按完成阶段显示，未知剩余时间返回 null。
- 场景：统一坐标、相机起点、视场、尺度依据及置信度、可行走表面、碰撞体、对象变换、已观察／创作表面、资源清单、生成与验收版本。
- 日志记录逐阶段实际时间；GPU 使用外部采样与框架峰值时分别注明范围，不能把权重文件大小当显存峰值。
- 快速版是合格的基础体验，完整版必须记录具体新增修正。渐进升级保留布局和位置；无法安全映射时留在快速版并提供明确切换，不静默传送。
- 旧任务状态通过兼容适配读入，标为未验证；不得把旧 FULL_READY 批量认定合格。

## 5. 按顺序执行的任务

### T00 基线与样片清单

目标：确认现状和设备，建立可重复对比。
允许：新增验证脚本、报告和本地证据；禁止：修改生成算法、安装模型。
输入／输出：当前工程、用户样片 → 硬件与依赖清单、真实行为表、样片编号与哈希；不存在的路径记录缺失，不伪造照片。
命令：现有前后端命令；新建 `backend/scripts/rebuild_baseline.py --help`，明确参数后运行。
视觉：保存原图与起点、前进、侧移、回头视角及连续运动录像；固定路线、窗口大小和参数。
回退／证据：只追加文件；报告命令输出、基线资源与版本，不下载或发布。

### T01 真实状态、计时与模式说明

目标：消除“文件生成＝完整版合格”和虚构耗时。
允许：models/store/main 中状态与阶段记录、前端状态显示、相关测试；禁止：换模型与重建算法。
输入／输出：现有任务 → 第4节状态、真实阶段时间及旧数据兼容；按钮保持快速、完整、渐进顺序，未实现能力明确标示。
命令：后端测试、前端构建；补充生成成功但质检失败、旧任务、取消／中断状态测试。
视觉：失败结果不能显示合格；未知时间不显示3–5／10分钟承诺；页面保留简洁说明，技术日志放详情。
回退／证据：兼容旧字段与数据库；提供状态截图、阶段记录和测试结果。

### T02 公共查看器修正

目标：稳定颜色、投影与资源切换，撤下跟镜头原图叠加。
允许：独立 viewer 模块、必要相机契约、原图对比入口；禁止：场景建模、整体视觉改版。
输入／输出：基线 GLB／原图 → 独立对比、正确长宽比与相机初始化、受控色彩设置。
命令：前端构建；涉及契约则后端测试。
视觉：固定起点比较纹理颜色；分别检验灯光、材质和色调映射，不能未诊断就全局关闭；破洞如仍存在据实展示为失败候选，不能声称本任务解决几何。
回退／证据：查看器变更独立可撤；提供同视角前后对比及切换录像。

### T03 GitHub 候选工具独立实测

目标：用实测选主体建模与分离工具。
允许：独立实验目录、适配脚本、依赖锁与报告；禁止：污染现有 MoGe 环境、接入主页面、上传照片。
输入／输出：清晰单物体、猫、遮挡街景主体 → 对比模型、正侧背面图、耗时和资源记录。先分离再建模；分离误差与建模误差分别记录。
候选：SAM 2；TripoSR；Hunyuan3D-2／mini；TRELLIS.2社区低显存分支。先核验版本许可和硬件，逐个试验而非一次装全套。主体生成不代表动作完成。
命令：新建 `backend/scripts/benchmark_asset_provider.py --help`；按其输入、provider、输出参数运行；记录上游原生命令及退出码。
视觉：检查轮廓、肢体、背面、纹理接缝、薄片和悬空；每个入选提供器至少第二张独立照片复验。
回退／证据：提供器互不影响；不合格不接入，报告可复现的失败原因。若全失败，停止相关分支，不拿替代物静默冒充。

### T04 室内结构验证

目标：稳定墙、地、顶与窗框，建立有限可探索空间。
允许：新增 indoor 几何实验模块、脚本；禁止：修改其他场景引擎或主 UI。
输入／输出：走廊、第二张房间 → 平面约束的结构、贴图、创作背面、地面与碰撞数据。使用消失线／法线等证据估计，不把全部房间强制成同一盒子；无法确定的尺寸标为估计。
命令：新建 `backend/scripts/benchmark_indoor.py --help` 后执行两张样片；几何测试检查平面、坐标与有效面。
视觉：门窗主要直线不呈波浪；前进、侧移、回头没有大片裸洞；眼高合理。绕行沙发需 T03 资产或明确简化几何，不能跨依赖虚报。
回退／证据：产物独立；失败保留分析和结构图，不替换主结果。

### T05 自然地形验证

目标：沿近景进入有限连续地形，体现远近尺度。
允许：新增 terrain 模块、脚本；禁止：修改主体、室内、主 UI。
输入／输出：雪山及不同自然照片 → 连续近中景地形、独立天空／远景、原图投色与简化补全、行走表面。先保留地形关系，再处理细节；悬崖等不能被错误抹平成通路。
命令：新建 `backend/scripts/benchmark_terrain.py --help` 并运行两张样片；测试有效网格、有限数值及行走采样。
视觉：起点可对应原照；前进进入地形而非穿贴图；坡面跟随、飞行、回头；远山不能被拉成长条。未知区域标为创作。
回退／证据：独立产物；记录可探索范围及为何设限，不能仅收紧范围隐藏缺陷。

### T06 场景契约与真实移动

目标：把通过验证的室内／地形接入同一查看器。
允许：契约、引擎路由、viewer控制器、对应测试；禁止：新模型和UI整体重做。
输入／输出：T04/T05通过产物 → 统一坐标、尺度、地面查询、碰撞、相机起点和资产配置。对象接地、朝向与大小须显式处理。
命令：前后端命令；测试碰墙、坡面、台阶、出生点、切换及异常数值。
视觉：完整录制走进去、绕过可绕障碍、回头；不能将 AABB 限制当成碰撞完成。
回退／证据：旧产物兼容读取；新引擎按模板启用；报告路线和运行性能。

### T07 街道与建筑

目标：街道分离主体后重建；建筑立面保持结构。
允许：street/facade模块与适配测试；禁止：改已通过的室内／地形核心。
输入／输出：用户俯拍街景、夜楼和各一张第二样片 → 道路／立面、独立人车树、估计位置及碰撞。依赖 T03/T06；缺少合格主体模型时该能力保持未完成。
命令：新建 `backend/scripts/benchmark_urban.py --help`，分别运行 street/facade；前后端相关检查。
视觉：俯拍起点下降、主体侧面、接地、朝向；窗线不扭曲、夜间颜色稳定；不承诺进入未拍到的建筑内部。
回退／证据：分模板关闭新引擎；保存第二样片结果与失败区域。

### T08 主体互动及其余类别

目标：动物、人物、食物、艺术／旧照片有实际区别且不挤掉互动主线。
允许：主体定位、动作提供器、独立 viewer 与分类策略；禁止：摄像头、手机、音乐。
输入／输出：每类至少两张照片 → 可用操作、动作资源、触发区域、冷却与回待机；艺术按内容选空间或主体。食物可做经验证的独立物体观察／局部响应，不强制人脸动画。
命令：新建 `backend/scripts/benchmark_subject_actions.py --help`；测试非目标点击不触发、重复点击、结束和资源失败；前端构建。
视觉：先清晰猫再遮挡猫；猫头响应但背景不随之晃动；人物特征不漂移；原背景与动作衔接不明显跳变。动作模型及驱动素材单独检查许可。
回退／证据：未验收动作不显示可用；不以整图抖动代替动作；逐类报告。

### T09 完整版与渐进升级

目标：真实增加结构／表面改善，并保留快速版可用性。
允许：任务编排、选定补全步骤、质量检查、切换；禁止：重新随机生成无关布局、虚构时间。
输入／输出：合格快速产物 → 固定布局上的增强产物及新增步骤清单。单GPU串行；完整失败保留快速；完整版不足以改善时返回未通过。
命令：前后端检查；模拟完整失败、取消、重启、切换位置不安全；新建 `backend/scripts/compare_scene_versions.py --help`。
视觉：同一路线并排比较至少一个明确修正；切换不突变到无关位置；质量验证与生成阶段分别显示。
回退／证据：保留旧资源引用，禁止覆盖快速资源；实际总耗时和每阶段证据。

### T10 导出、性能与八类总结

目标：验证真正交付，形成参赛证据。
允许：导出模块、资源优化、验证脚本和文档；禁止：对外提交、推送或默认上传案例。
输入／输出：通过场景 → 自包含离线包、可分享报告、八类能力矩阵。不能仅输出依赖 fetch 本地文件的网页后声称双击可用；用内嵌资源或验证过的方案解决 file:// 限制。
命令：前后端检查；新建 `backend/scripts/verify_export.py --help`；资源完整性检查。
视觉：另一台电脑断网双击、移动、互动、完整加载；目标浏览器固定路线记录帧率。暂定交互目标30fps，达不到则报告瓶颈，不只报平均值。
回退／证据：不删原资源；第二电脑未实测则该项未完成。记录包大小、首次加载时间、运行性能、离线验证与实际失败案例。

## 7. 最终验收和交接

八类每类至少两张不同照片；用户四张困难样片保留在矩阵中。每项记录通过／失败／未验证及证据，不能以简单照片成功覆盖困难样片失败。

质量底线：主要主体不撕裂，主要结构无明显弯折，指定路线无大片洞和严重拉伸，移动有合理尺度与碰撞，主体动作有真实触发且背景稳定，创作区域说明明确。自动检测辅助人工视觉验收，像素相似度不能替代空间可用性。

没有数据时不承诺3–5分钟或10分钟；按实际设备、输入类别与模式汇总耗时范围。没有新内容的full不是完整版合格；没有第二机验证的导出不是已完成分享。

- T00 是所有实施的基础，T01 的状态与证据记录支撑后续集成。
- T03 失败不阻止独立验证 T04 室内、T05 地形；T06 只能接入已经通过的引擎。
- T07 街道的独立主体依赖 T03，建筑立面可单独推进；不能因此宣称街道整体通过。
- T08 的动作验证可独立于主体三维建模进行；三维建模失败不等于点击动作必然失败。
- T09 仅升级已经验证的基础路线；T10 可以先验证已通过类别的导出，但八类总验收仍保持未完成。
- 部分子项通过时记录具体子项，不把整个阶段标为通过。

### 自动处理的范围

常规编译错误、参数问题、接口适配、显存不足的排查和已列候选切换，在任务范围内自行处理。免费模型下载和独立环境安装属于日后实施步骤，先核实来源、许可、D盘空间；系统权限仍按工具要求申请。不能未经许可把下载或环境改到C盘。

每次重试必须有新的诊断依据或调整。相同错误重复出现时停止盲目重跑，记录输入、参数、错误和尝试，转向不同方法或无依赖任务。不能为了通过测试修改测试预期、隐藏失败样片或删掉困难检查。

现有可用产物优先复用，避免重新下载权重和反复执行昂贵生成。需要降精度、缩小生成分辨率时必须重新检查质量，不能把节省显存当作效果已通过。

### 仅在确有需要时暂停相关工作

1. 需要付费、对外发送或发布、删除用户数据、超出已有授权的操作。
2. 必要文件或第二台测试设备不可访问，且没有等价验证途径。
3. 模型路线都无法达到约定效果，需要改变产品目标、接受更明显的外观变化或放宽离线要求。
4. 存在无法绕开的用户修改冲突或外部许可条件未满足。

暂停时交付已完成结果、失败证据、已尝试办法，以及一个具体待决定事项。继续推进不依赖该决定的工作；全部剩余事项均受阻时，明确结束为“部分完成、等待条件”，不能称全部完成。若缺少文件，应说明具体缺少什么，不虚构替代样片通过记录。

用户已接受适度简化和合理创作，不对范围内的普通实现选择反复确认。明显破洞、扭曲、假动画直接自行判失败修复；只有无法依据已确认标准作出的外观取舍才请用户看对比证据。

### 完成交付

交付可启动版本、已验证的启动命令、模型与依赖清单、样片矩阵、多角度录像、真实耗时／资源数据、导出验证和剩余问题。只有 T00—T10 的必需项及八类总体验收全部满足，才报告“全部完成”。阶段通过不替代最终用户体验验收。
