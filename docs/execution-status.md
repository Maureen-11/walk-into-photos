# 执行状态

更新时间：2026-09-14

## 本轮已完成

- 入口支持拖拽或点击上传 JPEG、PNG、WebP；正常照片不再有硬性拒绝分支。
- 数据模型扩展到八类正式模板和一个通用兜底模板：自然、室内、街道、建筑、动物、人物、食物、艺术/旧照片。
- PhotoPlan 现在返回推荐模板、兼容模板、推荐理由、场景描述、风险说明和三种质量模式所需的时间估计。
- 照片规划改为本地 Moondream 2B 适配器；模型不可用时进入明确标记的 local-rules-fallback，不调用在线聊天 API。
- SQLite 保存分析结果和任务状态；单 GPU ThreadPoolExecutor 一次只运行一个生成任务。
- 任务状态支持 QUICK_GENERATING、QUICK_READY、FULL_GENERATING、FULL_READY；渐进模式保持同一模板和坐标约定。
- manifest 改为模板感知，返回相机起点、安全边界、移动速度、飞行开关和生成区域说明。
- 前端查看器支持 360°拖动、WASD移动、F飞行、空格上升、C下降；上传区域支持文件拖拽。
- 导出接口当前可下载包含 scene.glb、manifest.json 和说明文件的离线场景包；源码交接包另含查看器资产，但导出包在另一台电脑断网双击打开仍未验收。
- T07/T08/T09/T10 的前置验收工具已加入：城市线索、主体动作契约、quick/full 比较门和离线包完整性检查；这些工具会保守地输出 `needs_visual_review` 或 `needs_offline_run`，不会把脚本通过当作体验通过。
- 后端规划测试 4/4 通过；前端 pnpm run build 通过；mock API 冒烟测试覆盖访问、上传、分析、任务轮询、manifest 和导出。

## 仍未通过的验收门

- Moondream 2B 约 3.85GB 权重已下载到 D 盘缓存；四张样片已在断网模式正确分类并完成模型释放测试。
- 四张样片的真实 MoGe 快速 GLB 已生成，覆盖率均为 0.9；这只证明几何管线可运行，不等于视觉体验已经通过。
- 真实配置端到端冒烟：离线 Moondream 将雪山识别为 natural_landscape，创建 quick 任务后真实 MoGe 返回 QUICK_READY，scene_id 可查询。

## 2026-09-13 复核更正

- 上述“四张样片覆盖率均为 0.9”是旧逻辑在没有 mask 输出时的固定占位值，不是实际测量；当前逻辑已改为无 mask 返回 `null`，不能把它当作质量证据。
- 当前已加入主体／场景统一协议、案例记录、单 GPU 分析与生成队列、重启中断与重试、起点重置和自包含离线包；这些代码通过测试，但尚未替代人工路线录屏和动作素材验收。
- 猫咪局部回应、真实地面碰撞、八类完整样片、完整版纹理补全和跨电脑离线打开仍未完成，详见 `docs/reports/vnext-execution-status-2026-09-13.md`。
- 当前 MoGe 输出仍是单次深度网格适配，尚未完成真正的地形、微缩主体、分层飞行、空间四引擎几何差异；不能把模板标签当作四套已完成引擎。
- 真实模式还没有完成四张样片的“走到山谷/沙发后方/街区下降/沿楼房飞行”视觉验收。
- 离线导出目前是 GLB + manifest ZIP；查看器资产已随源码交接包保留，但尚未证明导出包可在另一台电脑断网双击即玩。
- 尚未提交或推送 GitHub；提交前应先由团队审阅 diff 和测试证据。

## 2026-09-14 雪山浏览器验收

- 真实本地雪山流程已跑通：上传 → Moondream 规划 → landscape_journey → MoGe quick → QUICK_READY → 浏览器加载 GLB。
- 首次发现 MoGe 原始坐标与查看器坐标不一致，已加入 GLB 坐标归一化，并以自动化测试固定该约定；详情见 `docs/reports/task-4-snow-browser-validation.md`。
- 归一化后拖动环顾已实测 yaw/pitch 变化，但雪山几何仍稀疏，连续 WASD 路线、地面碰撞和回头验收仍未通过。

## 真实性边界

可以确认的是：统一产品入口、规划数据结构、任务持久化、通用交互和基础 MoGe/GLB 管线已实现并通过对应自动化检查。不能据此宣称八类照片都已完成真实空间复原；照片不可见部分仍是 AI 估计或程序化创作，质量必须用样片截图/视频逐类验收。
