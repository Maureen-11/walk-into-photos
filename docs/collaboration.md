# 协作说明

## 推荐协作方式

每位成员先阅读相同的文档，再分别把自己的理解、疑问和建议写成独立文件，并通过 Pull Request 合并。不要直接把一个人的想法覆盖到另一个人的文件里。

推荐流程：

1. 阅读 `README.md`、`AGENTS.md` 和 `docs/`；
2. 用自己的话说明项目目标；
3. 写出至少三个风险或疑问；
4. 选择愿意负责的工作部分；
5. 提交反馈文件和 Pull Request；
6. 决策确认后再进入实现。

## 分工优先于“谁更会写代码”

目前团队以学生为主，建议按可交付结果分工。每项工作都可以借助 AI 完成，但必须记录实际验证结果。

| 工作区 | 主要产出 | 适合负责的人 |
| --- | --- | --- |
| 用户流程与素材 | 上传流程、演示照片、隐私授权说明 | 对体验和内容感兴趣的人 |
| 模型实验 | MoGe/备用路线、耗时、显存和失败记录 | 愿意动手测试工具的人 |
| 页面与交互 | 上传页、分析页、查看器、错误提示 | 对页面展示感兴趣的人 |
| 研究与文档 | 赛规、参考项目、许可证和 README | 擅长整理和表达的人 |

一个人可以承担多个区域，但不能把“使用 AI 生成代码”直接写成“已经验证”。

## 当前协作问题

每位成员加入时，请回答：

- 每周大约可以投入多少时间？
- 更愿意负责用户流程/素材、模型实验、页面/交互还是研究/文档？
- 哪一类工作最不想负责？
- 是否愿意在电脑上安装依赖并记录测试结果？
- 能否参加演示和答辩？

## Pull Request 约定

- `main` 只保留已经确认的内容；
- 每个人使用自己的分支；
- 反馈文件放在 `docs/feedback/`；
- PR 标题格式：`feedback: 成员名对项目初步理解的反馈`；
- PR 描述写清楚改了什么、希望团队确认什么；
- 未经讨论不要直接修改别人的反馈文件。

## 当前阶段完成条件

- 至少一位成员提交项目理解和风险清单；
- 对第一条真实用户流程达成共识；
- 选出一个可以验证的最小路线；
- 形成清晰分工；
- 记录尚未验证的假设。
