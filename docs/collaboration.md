# 协作与分工

## 推荐工作方式

两位成员先各自阅读共同文档，再分别让自己的 AI 给出意见。每个人把意见写成独立反馈文件并提交 Pull Request，避免一个人的 AI 直接覆盖另一个人的思路。

推荐流程：

1. 阅读 `README.md`、`AGENTS.md` 和项目大纲；
2. 各自回答“我理解的目标是什么”；
3. 各自提出最多 3 个最重要的风险或问题；
4. 各自选择愿意承担的工作；
5. 合并后再更新决策记录；
6. 目标确认前，不开始大规模写代码。

## 分工不要先按前后端硬切

我们目前都是初学者，建议按“可交付成果”分工。下面每类都可以由人和 AI 一起完成：

| 工作包 | 主要产出 | 适合先询问谁 |
|---|---|---|
| 体验与素材 | 用户流程、示例照片、隐私和授权说明 | 对交互和内容更感兴趣的人 |
| 技术实验 | 路线比较、模型试跑、耗时和显存记录 | 愿意动手试工具的人 |
| 页面与演示 | 上传页、结果页、失败提示、演示脚本 | 对网页和展示更感兴趣的人 |
| 研究与文档 | 竞赛规则、参考项目、决策记录、README | 擅长整理和表达的人 |

一人可以承担主责，另一人做复核；不要把“会使用 AI”误写成“已经掌握工程能力”。

## 第一次分工讨论需要回答

每个人分别回答：

- 我每周大概能投入多少时间？
- 我最愿意做：体验/素材、技术实验、页面/演示、研究/文档中的哪一类？
- 我最不想承担哪一类？
- 我希望负责一个完整小模块，还是和对方结对完成？
- 我是否愿意在电脑上安装依赖、运行命令和记录结果？
- 我能否参加最终演示和答辩？

## 分支和 Pull Request 约定

- 共同文档在 `main` 分支；
- 每个人的意见放到自己的分支；
- 反馈文件命名为 `docs/feedback/YYYY-MM-DD-名字.md`；
- PR 标题使用：`feedback: 你的名字对项目大纲的反馈`；
- PR 中写清楚：新增了什么、希望团队决定什么；
- 未经讨论不要直接修改对方的反馈文件。

## 现阶段的完成定义

第一次讨论完成，不是“代码跑起来”，而是：

- 两个人都提交了独立反馈；
- 对第一版体验有共同描述；
- 选定一个可验证的最小路线；
- 形成初步分工；
- 写下仍然未知的风险。
