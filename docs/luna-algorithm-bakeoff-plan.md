# Luna 小计划书：先验证现成算法，再决定重做引擎

日期：2026-09-14。状态：资料核验完成；候选尚未在用户电脑实测。本轮仅新增计划，不安装模型、不修改运行工程。

## 结论与约束

优先做独立算法对比，不直接替换生成器。空间类最终目标仍是能前进、绕过近景并回头观察；主体类仍以点击/鼠标回应为目标，静态3D模型不算完成互动。

目标硬件为 Windows、RTX 4060 8GB；另一个6GB环境单独测量。两台电脑的显存不能直接相加。照片留在本机，环境、权重和输出放 D 盘。当前生产 .venv、模型缓存及用户未提交修改保留。

必须修正旧结论：单张深度图不是俯视地形高度图。天空无深度不等于所有黑色区域都由天空造成。剔除三角形、材质、裁剪平面、相机姿态及碰撞实现也可能制造问题。不能未经原版对照就认定 MoGe 无用，或认定高度场重写一定有效。

## 执行协议

Luna按R0→R1→R2→R3→R4顺序执行，通过一项后自动继续下一项，不为小任务反复询问。需要新费用、上传照片或扩大硬件范围时停止相关分支并报告。每项只改允许模块；先记录命令和输入，再运行。复杂对比和坐标适配使用high/xhigh；不为凑时长增加等待。

共同证据：输入SHA256、代码commit、权重来源/校验值、依赖、完整命令、冷/热启动耗时、峰值显存及内存、产物路径、截图与无剪辑视频。所有图片/权重/生成文件不入Git；报告使用相对样例ID。报告中不得将构建通过等同视觉通过。

所有新脚本命令如下是待实现接口，不能当作当前已存在命令。安装前先检查目标路径无已有环境；网络下载按权限流程执行。

## R0：固定基线和环境门槛

- 目标：确定失败来自当前后处理、查看器还是模型表征；保留当前版本证据。
- 允许：docs/reports/algorithm-bakeoff/、新建backend/scripts/bakeoff/；运行数据写walk-runtime-data/algorithm-bakeoff/。
- 禁止：修改生成器、控制器、数据库和旧场景文件；删除缓存；更改系统CUDA。
- 输入：雪山、另一张自然风景、走廊、街道、夜间楼房、猫图；缺样例记为缺失，不凭空说通过。
- 输出：baseline.json、hardware.json、原始姿态及移动轨迹记录。读nvidia-smi和系统内存/磁盘；为候选分别列Windows/WSL、权重许可及预计磁盘占用；大型世界模型若明显超资源，记录blocked_hardware，不下载安装。
- 验收命令：nvidia-smi；git status --short；新建脚本 --help；python -m json.tool baseline.json。
- 视觉：原拍摄位、前进、侧移、上升、下降、回头；每次记录相机数值和场景ID。不能只截最好看的一帧。
- 回退：本任务仅诊断，无产品回退需求；失败命令和环境问题写入报告。
- 证据：上述JSON、六方向画面和测试路径。

## R1：最小原版对照

- 目标：同一雪山/走廊，比较官方MoGe导出与当前后处理版本，避免误归因。
- 允许：隔离的D盘实验环境、backend/scripts/bakeoff/和报告；仅读取现有第三方源码。
- 禁止：覆盖生产环境/原始产物；直接删除当前补丁；改变输入照片内容。
- 输入：同样图片、官方MoGe用法及固定模型版本；输出两个独立GLB和相机标定。
- 方法：实验脚本分别启用/禁用自加深度稳定化、20倍中位边长剔面及context shell，记录每步覆盖和渲染差异。只更换一个变量；固定起点、FOV和运动轨迹。
- 验收：实现后运行 python backend/scripts/bakeoff/compare_moge.py --help，再用其已验证参数处理样片；读取产物并确认有限顶点/变换；原位重投影及移动画面对比必须同时存在。
- 视觉：确认灰面是否来自壳层，黑洞是否来自缺面或裁剪；检查sky半径与相机far的相对关系。不能把源码推断写成已复现原因。
- 回退：所有实验独立输出，生产路由不变。
- 证据：逐项开关对照、渲染图和结论；若原版明显更好，提出最小修正，不自动重写引擎。

## R2：现成候选独立实测

- 目标：先证明候选能在资源和许可范围内完成样片，再谈集成。
- 允许：D盘独立环境与候选源码目录、实验适配脚本、报告。
- 禁止：更换生产依赖、上传用户图片到在线Demo、租GPU、将静态视频当可玩场景。
- 顺序：FlashWorld先资源/依赖/全部权重许可检查；官方低显存路径9GB高于8GB，若找不到可核验8GB路径则标记资源受阻，不承诺必跑。3D Photo Inpainting作为分层补全对照。TripoSR单独处理物品/主体支线。SHARP只列研究参考，许可未明确覆盖本项目用途前不纳入产品实验。
- 输入输出：雪山+走廊为初筛，通过后加街道与楼房；TripoSR使用分割后的主体并保留原图作身份对比；输出实际PLY/SPZ/mesh及各自相机信息。
- 验收命令：各自环境中先运行官方CLI --help；FlashWorld依据README使用cli.py输入JSON及官方offload选项（参数先实查）；TripoSR使用python run.py INPUT --output-dir OUTPUT；3D Photo Inpainting使用python main.py --config 实验配置路径。
- 视觉：候选原版查看器先看，再看本地适配器；固定路径比较保真、空洞、拉伸、路径连续性、回头所见。小视差通过≠自由漫游通过。
- 回退：一次OOM允许一次官方低显存配置重试；继续OOM记录阻塞并转下一候选。隔离环境可保留，不主动删除。
- 证据：每个候选明确passed_limited_view / passed_navigation / failed_visual / blocked_hardware / blocked_license / blocked_dependency；不得合并成模糊“成功”。

## R3：通过者的最小查看器集成

- 前置：至少一个候选在R2有可重复的可用输出且许可允许目标用途。否则跳过并写R4决策。
- 允许：独立实验查看页面、一个新asset adapter、针对适配的测试；主业务接口只在实验验证后做小范围扩展。
- 禁止：全局升级Three.js以强行适配Spark；把Gaussian PLY交给GLTFLoader；沿用mesh向下射线作为高斯碰撞；将所有类别改为一个新模型。
- 输入输出：保留mesh_glb格式，增加独立gaussian格式分支；记录coordinate convention、起点、尺度、近远裁剪和tested navigation range。Gaussian显示与碰撞代理分开设计。
- 验收命令：前端pnpm run build；后端python -m pytest -q；新格式加载测试；断网载入本地资产。
- 视觉：与官方查看器同姿态比对；首帧、90度侧向、回头、路径中间帧都检查。无可行走碰撞代理时仅标实验查看器，不声称可行走已完成。
- 回退：通过实验开关返回旧路由，旧GLB/manifest继续可读；不批量迁移旧数据。
- 证据：浏览器录屏、版本对照、资源占用和明确能力范围。

## R4：八类覆盖表与是否重做的决策

- 目标：交付选型结果，不把硬件受阻写成算法不存在。
- 允许：报告、计划；禁止未经验证直接启动八类引擎重写。
- 输入：R0–R3全部证据。输出decision.md：选用模块、未通过类别、下一次最小实现任务。
- 八类映射：自然/室内/街道/建筑验证场景路线；动物/人物/食物验证主体保真与可用局部交互（本轮静态模型测试不算互动完成）；艺术/旧照片验证分层方案。每类正式验收至少两图；少于两图写未验收。
- 验收：报告引用真实产物路径和来源；任何“passed_navigation”必须有前进、绕过近物、回头视频，且不是靠回退原地实现无穿模。视觉比较中不得用灰面/天空罩遮住缺失结构后宣称补全。
- 回退与停止条件：候选均不满足8GB离线约束时，明确报告“本机可行方案尚未验证”，再给出一个自然场景连续地形的小型验证计划；不要直接铺开八类重写。高度场也要先证明深度到世界坐标、遮挡补全及纹理可用。
- 证据：综合表、失败理由、实测视频、明确下一步；没有视觉证据不得让用户再做唯一测试员。

## 给Luna的启动提示

请读取本计划和AGENTS.md，从R0开始顺序执行已满足前置条件的任务。先独立对照原版算法，再评估现成替代。每个任务的允许/禁止模块、输入输出、验收、视觉、回退、证据必须遵守。不得在主工程重复追加相机限制来代替场景修复。未满足资源或许可的分支记录阻塞，继续其他独立验证；新费用或上传照片需要用户另行同意。最终提供自己检验过的对比结果，而不是仅让用户刷新页面。
