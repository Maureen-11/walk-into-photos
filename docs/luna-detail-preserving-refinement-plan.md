# Luna 执行计划：保留精细度的场景美术升级

日期：2026-09-19。状态：R00、R01、R02 已完成；R04 的离线运行与自动路线证据已通过；R03 已生成 V49 材质灯光候选，等待用户视觉确认。

## 1. 已确认目标与优先级

用户已同意：先以朋友的走廊或客厅作为精修对照，再扩展其他指定照片。本计划选 I01 走廊为主样片，I02 客厅为复用验证。最终仍面向八张指定照片的小型可探索场景；八张照片的最终名单须依据现有素材清单确认，不把历史八类别或旧八世界清单直接当成已确定名单。动物交互属于后续阶段。

最高要求：新版本的可见精细程度不得低于朋友对应场景版本，同时改善杂乱、配色、构图和探索体验。照片原有空间方向、主要对象比例和特征必须可辨。近处是完整可探索区域，远处可作为不可达背景。

保留连续地面、风格化材质、统一美术语言与小区域探索。取消“最多八色”“极少实体”等任意上限。低多边形允许精细建模、材质纹理和阴影；不得把风格化解释为粗模。

storybook-v1 小屋和雪谷仅保留为未通过用户视觉验收的实验，不作为新版本质量基线。历史测试通过、GLB 导出成功和包完整均不代表视觉合格。

## 3. 美术验收契约

比较必须使用同一照片、相同视口（建议 1280×720）、相同相机位置/朝向/FOV、相同路线。既保留朋友原样截图，也保存候选截图。结构、材质调整阶段保持灯光一致；灯光阶段额外对照最终效果，防止靠变暗掩盖缺陷。

每个样片建立 `detail-inventory.md`，为每个关键细节记录：照片依据、基线截图位置、新版实现、近看截图、保留/改善/退步及理由。

| 维度 | 走廊检查内容 | 客厅检查内容 | 通过条件 |
|---|---|---|---|
| 照片特征 | 长向透视、左右门窗分布、尽端特征 | 沙发、桌子、窗墙关系与主要比例 | 不变成无关的通用场景 |
| 构造细节 | 门框、门扇、把手、窗框窗格、窗台、踢脚线、地面接缝、灯具 | 扶手、靠背、坐垫缝、桌面边缘与桌腿、柜体、窗框 | 基线已存在且有意义的细节不丢失；仅要求照片或基线支持的构件 |
| 材质 | 木、墙、玻璃、地面可区分 | 布、木、玻璃、金属可区分 | 近看有层次，远看不产生均匀噪点 |
| 构图和色彩 | 通行路线与空间尽端清楚 | 主体与陪衬区分 | 降低无意义碎色，不损失重点细节 |
| 光照 | 窗光方向、檐角/墙角、接地关系 | 家具接地、窗边明暗、局部重点 | 不过曝、不死黑、不靠浓雾遮挡 |
| 探索完整性 | 起点、近门窗、侧看、尽端回头 | 起点、桌边、沙发侧后方、回头 | 可达区域无破洞、穿墙、消失面和空壳 |

验收不是平均分：任何关键细节退步、主体特征丢失或移动严重缺陷都阻止发布。几何合并减少对象数可接受；删除可见细节来提高性能不可接受。第一张精修样片需用户确认风格后才扩展。

## 4. Luna 共用执行协议

下面每个任务都继承本节的禁止范围、验收命令、回退和证据规则，并叠加各自的具体要求；交给 Luna 时必须连同本节一起传递。

禁止范围：不得改动无关上传、数据库、模型下载、GPU 队列和在线调用；不得删除或覆盖朋友基线、用户修改、原始照片及已有产物；不得增加动物动画、手势等延期功能。主 UI 重做不属于本轮。查看器只在灯光或已复现交互问题确需修正时做最小改动。

实施方式：复杂几何、材质和交互任务使用 Luna high/xhigh。每次一个任务、一个明确变更集，不把所有阶段一次性塞进提示。任务完成且验收通过后连续推进；遇到审美确认门、权限阻塞或任务范围变化再汇报。编写计划与执行模型不是质量合格的证据。

验收命令从仓库根目录执行：

```powershell
git diff --check
Push-Location backend
& ..\.venv\Scripts\python.exe -m pytest -q
Pop-Location
```

仅在改动前端时读取 `frontend/package.json`，执行实际存在的类型检查/构建命令，不猜包管理器。每个任务补充自己可复现的生成命令及运行输出；不要把尚未编写的脚本宣称为现成命令。文档任务只检查内容和链接，无需跑全量测试。

输出统一放 `D:/Codex/2026-09-09/new-chat/outputs/detail-refinement/<run-id>/`，每次使用新目录。成功与失败证据均保留本地；生成资产和私有照片不进入 Git。性能报告记录设备、浏览器、视口、资源大小、绘制调用和帧时间，基线与候选同机比较。目标是指定体验机路线中位帧率至少 30 FPS，且无持续卡顿；不以减少关键细节换取性能。未测设备不能报告通过。

回退方式：默认切回旧样片选择，不改写旧产物；仅撤销本任务明确归属的补丁，不使用 reset --hard 或整文件恢复覆盖混合修改。先保存失败原因和对照证据。

完成报告必须分开列出：代码测试、包完整性、真实离线运行、视觉审阅、用户风格确认、性能。未测写未测，失败写失败。禁止用单张起点截图或测试数量替代完整路线验收。

## 5. 顺序任务

### R00：冻结可比较基线（只读工程）

- 目标：确认朋友版本及 I01/I02 可运行状态。
- 允许：读取代码、Git 状态、现有素材；新增本轮 docs/reports 和输出目录。
- 输入：本地/远程交接版本、catalog、原图、已有 GLB。
- 输出：baseline.json（提交、原图和资源哈希、相机、设备）、原图与起点/近景/侧看/回头截图、基线缺陷清单。
- 验收：逐项核对文件存在、哈希和实际加载结果；录制真实移动路线，不仅定位相机拍照。
- 回退/证据：保留基线，不修工程；缺素材或无法复现时明确报告，不能自造替代对照。

### R01：写出走廊细节清单与美术说明

- 目标：让“更好看且不降级”对应具体部位。
- 允许：本轮计划、detail-inventory、对照说明；不修改生成器。
- 输入：R00 原图与截图。
- 输出：必须保留清单、需要整理的噪声清单、主辅色/材质明暗关系、主体/陪衬/远景细节分配、五个固定观察点。
- 验收：每项都能对应照片或基线位置；不能只写“精致、电影感”。颜色数量不作为硬上限。
- 回退/证据：无法确定的部位标为创作建议；不将其描述成照片事实。

### R02：走廊结构与细节精修

- 目标：沿用朋友细节基础改善连续面、接缝和对象关系。
- 允许：新增独立 refinement 生成器模块与构建脚本、必要的相关测试；复用 pixel_scene 的现有逻辑，不串接新的几十层版本函数。
- 输入：I01 原图、冻结 V47 场景、R01 清单。
- 输出：新的 I01 GLB、布局/碰撞/manifest、确切生成命令。质量保持待审阅。
- 验收：执行共用命令；门窗近景有厚度和可辨细节，墙地连续；同机同角度比较无关键细节退步。验证通道净宽和相机眼高。
- 回退/证据：保留旧产物；逐项标注细节清单结果及对应截图。

### R03：走廊材质与照明

- 目标：改善碎色、平涂和接地关系。
- 允许：候选材质配置、新灯光预设；必要时修改在线/离线查看器读取预设的最小范围，不改变旧预设。
- 输入：R02 已验收结构。
- 输出：版本化材质/光照配置与候选场景。
- 验收：执行适用测试/构建；同视角检查玻璃、木、墙、地面与接触阴影；动态移动时无闪烁、摩尔纹、严重过曝。检查顶点色与材质色是否被重复相乘，检查所写预设是否实际被查看器读取。
- 回退/证据：材质和照明分别可回退；保留中性光与最终光的对照，不能仅在 manifest 中宣称已有光效。

### R04：走廊真实路线、离线交付与审美门

- 目标：验证可走、侧看、回头及朋友版本的质量下限。
- 允许：候选碰撞/运动配置、已复现问题的最小查看器补丁、导出/校验器的精确路由支持；不得放宽校验为任意前缀通过。
- 输入：R03 场景、R00 路线。
- 输出：同步操作录像/路线 JSON、五视角并排图、测试和性能报告、离线 ZIP。
- 验收：检查空格不滚页、失焦不持续移动、复位正确、碰撞不穿透。按仓库 AGENTS.md 读取 offline-verify 文档，用真实 file:// 验证，不用 localhost 替代；保留 catalog 中 offline_verification.status。先核对碰撞边界，不把不可达点写成已验证路线。
- 回退/证据：任一严重缺陷未解决则回到对应任务；自检通过后交给用户判断精细度和美感，用户确认前不扩展场景。

### R05：客厅复用验证

- 目标：证明方法能处理第二张不同照片，并不低于朋友 I02。
- 允许：独立客厅 refinement 模块、共享材质/资产中必要的参数化改进、相应测试和文档；禁止破坏已验收走廊。
- 输入：I02 基线、已确认美术标准。
- 输出：I02 候选与独立细节清单、同角度对照和完整路线。
- 验收：重复 R02–R04 的结构/美术/性能/离线标准；重点检查沙发轮廓、坐垫缝、桌边和桌腿、窗墙关系；在实际存在通道的条件下绕到家具侧后方，不凭空承诺能绕过贴墙家具。
- 回退/证据：只调整客厅或有证据的共享问题；走廊不回退，保留两者回归截图。

### R06：扩展其余六张指定照片

- 目标：总数达到八张，不降级为八个空模板。
- 允许：已确认照片对应模块、授权资产登记、输出和验收报告。
- 输入：R05 通过结果、经核对的八张素材清单和来源授权记录。
- 输出：逐张照片的特征清单、几何/材质方案、可探索边界、生成资产与证据。
- 验收：每张独立重复前述质量门；已有朋友同类基线的逐项比较；没有同类基线的，以已确认样片的近景构造和材质层次建立具体参考，不能伪造旧版对照。雪山检查地形尺度和雪岩分区，小屋检查屋檐/门窗/石墙，海岸检查岸线/岩石/水面接合。
- 回退/证据：单张失败不影响已通过场景；总体进度按已通过数量报告。来源/授权不明的资产不并入交付。

### R07：集成与最终交付

- 目标：让八张场景在同一入口可体验，并能解释智能体实际做了什么。
- 允许：场景注册/选择、必要 UI 接口、导出、交接文档与回归；整体 UI 改版另行处理。
- 输入：已验收场景和真实生成日志。
- 输出：统一体验入口、逐场景结果表、可复现启动/生成说明、离线验收报告、素材署名和失败记录。
- 验收：逐场景检查入口确实加载新资源；缓存、资源哈希与页面版本相符；如保留快速/完整/渐进模式，必须有真实不同产物和升级验证，不能重复同一文件冒充完整版。实测耗时如实显示。
- 智能体说明：分别记录照片理解、方案选择、实际调用工具、质量检查、失败修正；手工固定资产和本地规则明确说明，不能称为模型生成或自主推理。
- 回退/证据：入口可恢复到已验收旧版本。代码提交应只包含本轮文件并核对差异；推送/发布按用户授权执行，生成文件不混入源码提交。
