## 3. 当前问题（作为修正前证据）

1. `geometry.py` 以 `x/y/z` 分别缩放并将网格平移到人为运动范围，破坏了照片投影与相机坐标的对应关系。
2. 前端在加载 GLB 时额外使用 `scale={1.1}`，相机使用固定 `68°` FOV；这两个隐式参数没有和 MoGe 的内参绑定。
3. 查看器没有保存 `intrinsics`、`image_size`、`camera_to_world`、`world_scale`、`near/far` 和坐标系版本，无法判断当前画面是否仍对应原始拍摄位置。
4. 旧版 movement profile 直接把相机放到人工设定的地面高度；真实场景尚未完成地面、碰撞和路线验收。

## 4. 可复现路径

1. 在 `backend` 启动 FastAPI，在前端启动 Vite。
2. 打开 `/`，进入 `walk-demo`，上传一张本地照片。
3. 选择真实 MoGe quick 或 full 生成并打开场景。
4. 记录第一帧相机是否仍位于照片投影原点，再记录前进、后退和旋转是否出现空场、穿模或纹理拉伸。

本记录阶段不把旧结果标为成功；旧场景保留仅用于前后对比和回退。

## 5. 隐私与回退

- 原始照片和模型缓存仍在本地运行数据目录，不提交到仓库。
- 当前真实模式使用本地 MoGe；没有把照片上传到外部聊天或第三方接口。
- 后续生成使用新的 scene id。出现回归时可以继续打开旧 scene，或只回滚本次提交涉及的代码文件，不删除运行数据。
