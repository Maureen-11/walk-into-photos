# Task 4：雪山场景本地浏览器验收

日期：2026-09-14
输入：用户提供的雪山 JPEG（仅在本机处理）
模式：真实本地规划 + MoGe v2 快速生成

## 通过项

- 本地页面可接受照片，并进入规划确认步骤。
- Moondream 本地规划将照片识别为 `natural_landscape`，推荐 `landscape_journey`。
- 用户确认“快速体验”后，真实 MoGe 任务进入 `QUICK_READY`，页面可加载 GLB 和 manifest。
- 查看器水平拖动可改变 yaw（实测 `0.00 → -1.00`），垂直拖动可改变 pitch（实测 `0.00 → 0.50`）。这证明环顾输入已接入查看器。
- 查看器现在暴露本地验收用的相机位置读数，起点实测为 `0.00 / 0.10 / -0.30`；该读数不改变场景交互，也不上传数据。

## 发现并修复的问题

第一次真实生成的 GLB 边界约为 `x=-1018..1174、z=-1595..-10`，但 manifest 的相机/移动范围仍是人类尺度的 `x=-4..4、z=-12..1`。结果是相机几乎位于模型外，首帧只看到空背景。

新增 `normalize_glb_for_viewer()`：生成真实 MoGe GLB 后，把模型映射到模板的查看器坐标系，保留 x/z 的主要比例，并把最近表面放到相机前方。修复后的雪山 GLB 边界为：

```text
x=-3.68..3.68
y=-0.60..0.176
z=-12.96..-1.00
```

该转换有自动化测试，当前后端测试为 `16 passed`。

## 尚未通过的验收门

- 修复后首帧能够看到雪山纹理/几何片段，但仍较稀疏，尚不能称为“走进山谷”。
- 尚未证明连续按住 WASD 可以走过 manifest 中的三个路线检查点；当前浏览器自动化只能可靠发送离散按键，不能把它当作路线通过证据。需要人工在本地页面按住 W 录屏，或下一项任务补充可重复的输入测试。
- 未验证真实地面碰撞、回头路线、飞行高度和边界阻挡。
- manifest 的几何覆盖率仍为 `null`，因为 MoGe 本次没有输出可用 mask；不能用它作为质量分数。
- R 键重置已复测：拖动到 `yaw=-1.00` 后按 R，查看器文案回到 `视角 0.00 / 0.00`；这只证明起点/朝向重置，不等于路线碰撞通过。
